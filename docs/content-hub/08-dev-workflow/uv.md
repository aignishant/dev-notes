# `uv` Package Manager

## What is `uv`?

> *"`uv` is an extremely fast Python package and project manager written in Rust, from Astral (the makers of Ruff). The Content Hub uses `uv` instead of pip/poetry for speed, deterministic lockfiles, and a unified interface for envs, dependencies, running code, and installing tools."*

## Why `uv` Over pip/poetry?

| | pip | poetry | **uv** |
|---|---|---|---|
| **Speed** | Baseline | Slower | **10-100× faster** |
| **Lockfile** | No | Yes | Yes (`uv.lock`) |
| **Project mgmt** | No | Yes | Yes |
| **Run-in-env** | `pip install`-then-run | `poetry run` | `uv run` |
| **Tool install** | `pip install` (pollutes env) | Limited | `uv tool install` (isolated) |
| **Python version mgmt** | No | No | **Yes** |

## Core Commands You'll Use Daily

```bash
# Sync project deps (creates .venv + installs)
uv sync
uv sync --dev                   # also install dev deps

# Add a new dep
uv add requests
uv add --dev pytest
uv add git+https://github.com/org/repo.git

# Remove a dep
uv remove some-package

# Run something in the project env
uv run python script.py
uv run pytest
uv run mp test

# Install a global tool (isolated env)
uv tool install mp --from git+https://github.com/chronicle/content-hub.git#subdirectory=packages/mp

# One-shot run a tool
uvx --from git+... mp --help

# Lock without installing
uv lock
```

## The `uv.lock` File

Every integration commits its `uv.lock`. Contains:

- Every transitive dependency
- Exact version + hash of each
- Platform markers

**Why commit it:** reproducible builds. Without it, a third-party library's patch release could break CI silently. With it, everyone — dev, CI, customer — installs the exact same dependency graph.

!!! warning "Never hand-edit uv.lock"
    It's regenerated by `uv sync` / `uv lock`. Hand edits create checksum mismatches that fail verification.

## `pyproject.toml` + `[tool.uv.sources]`

The Content Hub's twist: dependencies are often pointed at **local wheel paths** via `[tool.uv.sources]`:

```toml
[project]
dependencies = [
    "tipcommon",
    "environmentcommon",
]

[tool.uv.sources]
tipcommon = { path = "../../../../packages/tipcommon/whls/TIPCommon-2.0.6-py3-none-any.whl" }
environmentcommon = { path = "../../../../packages/envcommon/EnvironmentCommon-1.0.2/EnvironmentCommon-1.0.2-py2.py3-none-any.whl" }
```

This lets each integration pin its own TIPCommon version without publishing to a public index.

For Git-sourced deps (like `soar-sdk`):

```toml
[dependency-groups]
dev = ["soar-sdk"]

[tool.uv.sources]
soar-sdk = { git = "https://github.com/chronicle/soar-sdk.git" }
```

## Dependency Groups

Production dependencies → `[project.dependencies]`.
Development dependencies → `[dependency-groups.dev]`.

```toml
[project]
dependencies = ["requests", "tipcommon", "environmentcommon"]

[dependency-groups]
dev = [
    "pytest>=8.0.0",
    "pytest-cov",
    "integration_testing",
    "soar-sdk",
]
```

**Only** production deps ship in the deployable zip. Dev deps stay local for testing/linting.

## Python Version Pinning

Each integration has `.python-version`:

```
3.11
```

And `pyproject.toml`:

```toml
requires-python = ">=3.11,<3.12"
```

`uv` honors both. `uv sync` will error if your local Python isn't 3.11.x.

## Creating a New Integration's Environment

```bash
cd content/response_integrations/third_party/community/my_integration
uv init                         # Create pyproject.toml
uv add requests tipcommon environmentcommon
uv add --dev pytest integration_testing soar-sdk
uv sync --dev
```

## Running Code Inside the Env

```bash
# One-shot
uv run python my_script.py

# Or activate persistently
source .venv/bin/activate
python my_script.py
```

## Lockfile Regeneration

```bash
uv lock                         # Regenerate uv.lock without installing
uv sync                         # Regenerate + install
uv lock --upgrade               # Bump all deps to latest compatible
uv lock --upgrade-package requests
```

## Common `uv` Gotchas

| Gotcha | Fix |
|---|---|
| Forgetting `--dev` → dev deps missing | Always `uv sync --dev` in dev environments |
| Hand-editing `uv.lock` | Never. Use `uv lock` to regenerate |
| Wrong Python version active | `uv sync` errors; install correct Python via pyenv or similar |
| Local wheel path broken after a move | Update `[tool.uv.sources]` relative paths |
| Caching stale wheels | `uv cache clean` |
