# 📚 6-month study plan

> 26 weeks. 4,000+ problems. 2–3 hours per day. The deepest plan — for beginners starting from zero.

---

## Who this plan is for

✅ You're a **true beginner** — Python is new or rusty, you've never solved a LeetCode problem, "Big-O" is a phrase you've heard but can't define.
✅ You have **6 months** (or more) before any interview.
✅ You can sustain **2–3 hours per day** — gentle but consistent.
✅ You want to be **genuinely good**, not just interview-ready.

This is the plan I'd give my younger self. It builds intuition that lasts a decade, not just a quarter.

---

## The bargain this plan makes

| Buy | Cost |
|---|---|
| Deep intuition, not memorization | 6 months of consistency |
| 4,000+ problems with multiple repetitions | Less time per day = slower visible progress |
| Every section of the bible covered | Long timeline = motivation risk |
| 20+ mock interviews | You must protect the habit ruthlessly |
| You'll teach others by month 4 | — |

## The 6 phases (one phase per month)

### Month 1 — Python + Foundations (the floor)

You won't solve a single hard problem this month. You'll build tools.

**Weeks 1–2: Python**
- Read [Python crash course](../01-foundations/python-crash-course-for-dsa.md) section by section, code along
- Read [Python tricks](../01-foundations/python-tricks-for-interviews.md), code each example
- Read [STL deep-dive](../01-foundations/python-stl-deep-dive.md), play with `collections`, `itertools`
- 5 easy problems per day (not patterns yet — just to type Python)

**Weeks 3–4: Complexity + recursion**
- Read [Time complexity](../01-foundations/time-complexity-explained.md), [Space complexity](../01-foundations/space-complexity-explained.md), [Big-O cheatsheet](../01-foundations/big-o-cheatsheet.md)
- Read [How to think recursively](../01-foundations/how-to-think-recursively.md) twice
- Read [How to approach any problem](how-to-approach-any-problem.md) — internalize the 7 steps
- 5 easy problems per day, focus on correct complexity analysis

**End of month 1:** ~140 easy problems solved. Big-O reflexive. Python fluent.

**Mock #1** at end of month 1 — easy-only, you should crush it.

### Month 2 — Linear data structures (arrays, strings, hash, linked lists)

**Week 5:** Arrays basics, slicing, mutation, two pointers
**Week 6:** Sliding window, prefix sums, Kadane
**Week 7:** Strings, hash maps, sets
**Week 8:** Linked lists (basics, reversal, cycle, merge)

7 problems per day across the week. End of month 2: ~340 total problems.

**Mock #2** end of month 2.

### Month 3 — Stacks, queues, heaps, recursion, backtracking

**Week 9:** Stacks (incl. monotonic) + queues + deques
**Week 10:** Heaps (priority queue, top-K, K-merge)
**Week 11:** Recursion deep-dive + classic problems
**Week 12:** Backtracking (subsets, permutations, combinations, N-queens, sudoku)

7 problems/day. End of month 3: ~540.

**Mock #3** mid-month, **Mock #4** end of month.

### Month 4 — Trees and graphs

The single hardest month. Plan for slowdowns.

**Week 13:** Binary trees (DFS traversals, recursion patterns)
**Week 14:** Tree BFS, BST, advanced tree patterns (LCA, diameter, serialize/deserialize)
**Week 15:** Graphs basics (BFS, DFS, components)
**Week 16:** Topological sort, cycle, Dijkstra, MST, advanced

7–8 problems/day. End of month 4: ~770.

**Mock #5, #6, #7** spread across this month — the topic is dense, more mocks help.

### Month 5 — Dynamic programming + patterns

**Week 17:** DP — 1D essentials (Fibonacci, climb stairs, house robber, coin change)
**Week 18:** DP — 2D essentials (LCS, edit distance, palindromic subsequence)
**Week 19:** DP — knapsack family + harder problems (regex, burst balloons)
**Week 20:** All 20 patterns — read each, solve 4 problems per pattern

7–8 problems/day. End of month 5: ~990.

**Mock #8, #9, #10** — DP is what loses interviews; mock heavily.

### Month 6 — System design + advanced + behavioral + polish

**Week 21:** System design fundamentals (databases, caching, message queues, microservices)
**Week 22:** 2 Tier-1 system design projects (URL shortener, Twitter feed)
**Week 23:** 2 more Tier-1 + 1 Tier-2 (YouTube, Uber, Instagram)
**Week 24:** Behavioral STAR + 10 personal stories + advanced topics (tries, union-find, segment trees skim)
**Week 25:** Re-do the bible's 100 hardest problems from memory
**Week 26:** Mock-heavy week — 6 mocks across 7 days. Final 2 days = light review only.

End of month 6: 1,200+ problems mastered, 20+ mocks done.

## Daily rhythm

```
07:00 — wake, exercise
07:30 — breakfast, light reading (10 min review of yesterday)
08:00 — block 1 (1 hr): morning re-do — 2 problems from memory
... day job / classes ...
20:00 — block 2 (1.5 hrs): topic + 2–3 problems
22:00 — log progress, sleep
```

Weekends: 3 hours. Saturday for new content, Sunday for re-do + mock.

---

## The repeating "re-do" cycle (the secret of this plan)

Every Friday: re-solve **5 problems from earlier in the week** without notes.
Every 4 weeks: re-solve **20 problems from the previous month** without notes.
End of month 6: re-solve **40 of your "I marked this hard" problems** in week 25.

This is what converts knowledge into ownership. Skipping the re-do cycle is the #1 mistake people make in long plans.

---

## Self-check tests

End of every month: take **6 fresh problems** from any topic you've covered. Solve in 30 min each. Score:

- 5–6/6 → on track
- 4/6 → fine, raise weekly volume slightly
- 3/6 → spend the next weekend re-grinding the past month
- ≤2/6 → repeat the past month's content (yes, the whole month) — better to lose a month here than fail the interview later

---

## Falling behind?

This plan has slack built in (life happens). But if by end of month:

- **Month 2:** <250 problems → drop linked-list deep dive, focus on arrays + hash
- **Month 4:** <600 → drop graph advanced (Dijkstra, MST), do basics only
- **Month 5:** <850 → drop pattern-by-pattern review in week 20
- **Month 6:** <1,000 → reduce system design to 2 projects, save mocks for last week

Switch to **3-month fast-track** at any point if you find a sudden interview opportunity — you'll have months of foundation to build on.

---

## Ahead of schedule?

By month 3 if you're 100+ problems ahead:
- Compress to **3-month fast-track**, take a 3-month break, come back fresh
- Or: keep going — add advanced topics (tries, union-find, segment trees) in month 4, more system design in month 6
- Or: start contributing to open source. Real projects build interviewing intuition that no problem set can teach.

---

## The final week

Week 26 is sacred:
- 6 mocks
- 2 days of light review
- Sleep 8+ hours every night
- Stop adding new content

You've earned this. Show up calm.
