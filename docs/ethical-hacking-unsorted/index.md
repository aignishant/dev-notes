# Redshift — Ethical Hacking Mastery

!!! danger "Read this first"
    Every technique in this documentation is for **authorized testing, lab practice, and detection engineering only**. Running these tools against systems you do not own or do not have explicit written permission to test is a federal crime in the United States under the **Computer Fraud and Abuse Act** (18 U.S.C. § 1030) and carries similar penalties in most other jurisdictions. You are responsible for your own actions.

## Who this is for

You are:

- A **SOAR engineer**, detection engineer, or security analyst who wants to go offensive.
- Already comfortable with Python and the security-operations mindset.
- Aiming for roles at **CISA, NSA, FBI Cyber, DoD, DHS**, or cleared contractors (MITRE, Booz Allen, Leidos, ManTech, Mandiant, etc.).
- Willing to spend **9–15 months** grinding through labs, CTFs, and certifications.

## How this site is organized

The curriculum is **16 Parts, 66 Modules**. Each module has:

- Clear concept explanation (attacker-logic first).
- **At least 5 Python scripts** (concept → production tool → real-time demo → industry scenario → toolkit contribution), plus a blue-team detection pair.
- Real-world engagement scenarios tied to a specific industry vertical.
- Lab exercises you run against your own targets.
- CVE/breach callouts so you know where the technique showed up in the wild.
- Detection angles — what the defender sees, how to write the Sigma/YARA rule.

## Your north-star deliverable

By the end, you will own:

1. A fluent, documented understanding of offensive security from OSINT to exploit dev to APT emulation.
2. **`redshift-toolkit`** — a 300+ script Python package you wrote yourself, publicly visible on GitHub as portfolio evidence.
3. OSCP + 1–2 other relevant certifications.
4. A resume and interview answer bank tuned for US federal and cleared-contractor hiring pipelines.
5. An active clearance (Secret minimum, TS/SCI ideal) adjudicated or in-progress.
