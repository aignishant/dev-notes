📊 ML Fundamentals & Core Concepts

In traditional programming, you write explicit rules. In Machine Learning, you give the computer data + expected outputs, and it learns the rules by itself.

Real-World Example: Email Spam Filter

# Traditional: 1000 manual rules
def is_spam(email):
    if "lottery" in email or "free money" in email:
        return True
    return False  # Miss new patterns!

# ML: Learn patterns from data
from sklearn.naive_bayes import MultinomialNB

vectorizer = TfidfVectorizer()

Interview Decision Framework

"I have labeled data" → Supervised | "Find patterns in unlabeled data" → Unsupervised | "Sequential decisions with rewards" → Reinforcement

Total Error = Bias² + Variance + Irreducible Noise

Bias = Model too simple → underfits → misses patterns. Variance = Model too complex → overfits → memorizes noise.

How to Detect & Fix

SignalProblemFix
Train ≈ Test (both bad)High Bias (Underfit)More features, complex model, less regularization
Train >> Test (big gap)High Variance (Overfit)More data, regularization, dropout, simpler model
Train ≈ Test (both good)Good fit ✅Deploy!

Scenario: "99% train accuracy, 60% test accuracy. What's happening?"

Answer: Classic overfitting. The 39% gap shows the model memorized training data. Fix: add L2 regularization, get more data, use dropout, or try cross-validation to find the right model complexity.

BatchNorm normalizes layer inputs to mean=0, std=1 within each mini-batch. Then applies learnable scale (γ) and shift (β).

Why It Helps

  • Allows higher learning rates (faster training)
  • Reduces sensitivity to weight initialization
  • Acts as mild regularization (noise from batch statistics)
  • Smooths the loss landscape

BatchNorm vs LayerNorm

TypeNormalizes acrossUsed in
BatchNormBatch dimensionCNNs, MLPs
LayerNormFeature dimensionTransformers (batch-size independent)

If weights start too large → exploding gradients. Too small → vanishing gradients. Too uniform → all neurons learn the same thing.

Answer: Likely exploding gradients from bad initialization. Fix: (1) Use Kaiming init for ReLU networks, (2) Add gradient clipping, (3) Add BatchNorm/LayerNorm, (4) Use residual connections (ResNet-style).

The Bottleneck Problem

Compressing an entire paragraph into ONE vector loses information. Solution: Attention mechanism — decoder can look at ALL encoder states, not just the last one.

Standard RNN only sees left context. Bidirectional processes sequence both left-to-right AND right-to-left, then concatenates hidden states.

  • Use: Classification, NER, POS tagging — when you have the FULL sequence at prediction time
  • Don't use: Text generation, real-time streaming — can't look ahead

BERT is essentially a bidirectional Transformer encoder — it can see all tokens simultaneously.

During training, instead of feeding the decoder's own (possibly wrong) predictions, feed the ground truth previous token. This speeds up training dramatically.

Exposure bias: At inference, the model sees its own predictions (which may be wrong), not ground truth. This mismatch can cause cascading errors.

  • Scheduled sampling: Gradually reduce teacher forcing during training
  • Beam search at inference: Explores multiple paths to reduce error accumulation

In vanilla RNN: gradient = ∏(W × σ'). After T steps, if eigenvalues of W < 1 → gradient → 0 (vanishes). If > 1 → gradient → ∞ (explodes).

LSTM solution: The cell state acts as a "highway" for gradients. The forget gate controls a linear path (no squishing activation) so gradients can flow unchanged through time.

This is conceptually identical to ResNet skip connections — both create shortcut paths for gradient flow.

🤖 Transformers & Attention Mechanism

Self-attention lets every token look at every other token simultaneously. No sequential bottleneck like RNNs.

Attention(Q,K,V) = softmax(QKᵀ / √d_k) × V

def self_attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, -1e9)
    weights = F.softmax(scores, dim=-1)
    return torch.matmul(weights, V)

Key Components

  1. Multi-Head Attention: 8-96 heads learn different relationship types
  2. Positional Encoding: Sin/cos or learned positions
  3. Feed-Forward Network: MLP after attention
  4. Residual + LayerNorm: Enable very deep networks

Self-attention is permutation invariant — it treats tokens as an unordered set. But word ORDER matters! "Dog bites man" ≠ "Man bites dog".

Two Approaches

  • Sinusoidal (original Transformer): Fixed sin/cos functions at different frequencies. No learned parameters.
  • Learned positional embeddings (GPT, BERT): Train a position embedding table. More flexible.
  • RoPE (Rotary, used in LLaMA): Encodes relative position via rotation matrices. Better for long sequences.
  • ALiBi (Attention with Linear Biases): Adds linear bias based on distance. Extrapolates to longer sequences.

Single attention head can only focus on ONE type of relationship at a time. Multiple heads learn DIFFERENT relationships in parallel.

  • Head 1: Learns syntactic relationships (subject-verb)
  • Head 2: Learns semantic relationships (synonyms)
  • Head 3: Learns positional relationships (nearby words)
  • Head 4: Learns coreference (pronouns → nouns)

Formula: MultiHead(Q,K,V) = Concat(head₁,...,headₕ)Wᴼ where headᵢ = Attention(QWᵢQ, KWᵢK, VWᵢV)

Scenario: "Why does GPT-3 use 96 attention heads?"

Answer: More heads = more relationship types learned simultaneously. Each head has smaller dimension (d_model/n_heads), so compute stays manageable. Empirically, more heads with smaller dims works better than fewer large heads, up to a point.

During autoregressive generation, each new token requires attending to ALL previous tokens. Without caching, we'd recompute K and V projections for all past tokens at every step → O(n²) compute.

KV Cache: Store K and V matrices from previous tokens. Each new token only computes its own Q, K, V and attends to cached K, V → O(n) per step.

Memory cost: KV cache for a 70B model with 128K context can be 40+ GB. This is why long-context models need lots of GPU memory even for inference.

MoE: Instead of one large feed-forward network, have multiple smaller "expert" networks. A router network selects which 2-4 experts to use for each token.

  • Total params: Very large (e.g., 1.7T for Mixtral 8x22B)
  • Active params per token: Much smaller (e.g., ~39B) → fast inference
  • Benefit: Large capacity without proportional compute cost

Mixtral 8×7B has 47B total params but only 13B active per token. Matches Llama 2 70B quality at 6× less compute.

Standard attention computes full N×N attention matrix → O(N²) memory. For 128K tokens, this matrix alone would be 64GB!

Flash Attention: Computes attention in tiles that fit in GPU SRAM (fast memory), avoiding materializing the full N×N matrix. Result: 2-4× speedup, O(N) memory, enables contexts of 128K+ tokens.

Why Calculus Matters

The gradient tells us how to adjust each weight to reduce loss. Without calculus (chain rule), we can't train neural networks.

  • Partial derivative ∂L/∂w: How much loss changes when weight w changes by tiny amount
  • Chain rule: ∂L/∂w₁ = ∂L/∂ŷ × ∂ŷ/∂z × ∂z/∂w₁. Backprop IS the chain rule applied to computation graphs.
  • Gradient descent: w_new = w_old - lr × ∂L/∂w

Key Interview Questions

  • "Derivative of ReLU?" — 1 if x > 0, 0 if x < 0 (undefined at x=0, usually set to 0)
  • "Derivative of sigmoid?" — σ(x)(1-σ(x)). Maximum at x=0 (0.25), approaches 0 at extremes → vanishing gradient
  • "Why does sigmoid cause vanishing gradients?" — Max derivative is 0.25, so after 10 layers: 0.25^10 ≈ 0.000001. Gradients vanish.
  • Entropy H(p): Measures uncertainty. Higher entropy = more random. Coin flip: H = 1 bit. Biased coin (99/1): H ≈ 0.08 bits.
  • Cross-Entropy H(p,q): Measures how well distribution q approximates true distribution p. This IS our classification loss function!
  • KL Divergence: KL(p||q) = H(p,q) - H(p). How different q is from p. Always ≥ 0. Used in VAEs, knowledge distillation.

Connection to ML: Cross-entropy loss = -Σ yᵢ log(ŷᵢ). Minimizing this = making predicted distribution match true distribution.

Common Causes

  1. Train-serve skew: Feature computation differs between batch training and real-time serving. Fix: use Feature Store (Feast) for consistent computation.
  2. Missing features at serve time: Some features take time to compute (aggregations). Fix: pre-compute and cache in Redis.
  3. Data type mismatch: Training uses float64, serving sends int. Fix: strict input schema validation.
  4. Latency requirements: Model too slow for real-time. Fix: quantize, distill, or serve simpler model for real-time + complex model for batch.

  5. Active learning: Start with random predictions, have humans label most uncertain cases, retrain

  1. Don't argue — experiment: Train both, compare on same CV split with same metrics

Multilingual ML Challenges

  1. Tokenization: English-trained tokenizers fragment non-Latin scripts into many tokens → longer, more expensive, worse performance
  2. Training data: Most datasets are English-heavy. Hindi may have 10x less training data.
  3. Evaluation: Need native speakers to evaluate output quality

Solutions

  • Use multilingual models: mBERT, XLM-RoBERTa, multilingual embeddings
  • Fine-tune on target language data
  • Translation-based: Translate to English → process → translate back
  • Use multilingual LLMs (GPT-4, Claude support 95+ languages)
